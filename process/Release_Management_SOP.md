# 📦 发布管理 SOP

> **目标**: 规范化版本号管理、发布流程、回滚策略

---

## 🔢 语义化版本 (Semantic Versioning)

```
MAJOR.MINOR.PATCH
  │     │     └── 修复: 向后兼容的 Bug 修复 (1.0.0 → 1.0.1)
  │     └──────── 功能: 向后兼容的新功能 (1.0.0 → 1.1.0)
  └────────────── 破坏: 不兼容的 API 变更 (1.0.0 → 2.0.0)
```

| 版本 | 平台示例 | 说明 |
|------|---------|------|
| versionName | "1.2.3" | 用户可见 (App Store / Play Store) |
| versionCode | 1002003 | 内部递增 (1×1000000 + 2×1000 + 3) |
| Build | 42 | CI 构建编号 |

## 📋 发布检查清单

```
═══════════════════════════════════════
发布前 (代码冻结 → 测试 → 构建)
═══════════════════════════════════════
□ 1. 所有 PR 已合并到 main
□ 2. CI/CD 流水线全部通过 (build + test + lint)
□ 3. 单元测试覆盖率 ≥ 80%
□ 4. E2E 测试全部通过
□ 5. 性能回归测试通过 (启动时间/内存/帧率)
□ 6. 无障碍审计通过
□ 7. 隐私清单已更新 (iOS PrivacyInfo / Android Data Safety)
□ 8. 依赖库无已知安全漏洞 (npm audit / SPM dependency check)
□ 9. CHANGELOG.md 已更新
□ 10. 版本号已递增 (versionCode + versionName)

═══════════════════════════════════════
提交审核
═══════════════════════════════════════
□ 11. 应用描述/截图已更新 (如有变化)
□ 12. 审核备注已填写 (说明新功能/修复内容)
□ 13. 内购/订阅已配置 (如适用)
□ 14. 提交审核

═══════════════════════════════════════
发布后
═══════════════════════════════════════
□ 15. 监控崩溃率 (< 1%)
□ 16. 查看用户评价 (24h 内回复差评)
□ 17. 验证关键功能正常
□ 18. 记录发布数据 (DAU/留存/评分)
```

## 🚨 紧急修复流程 (Hotfix)

```
发现问题 (崩溃率 > 1%)
    ↓ 15 分钟内
确认根因 → 创建 hotfix 分支
    ↓ 2 小时内
修复代码 → 单元测试 → PR → Code Review
    ↓ 1 小时内
构建 → 内部测试 → 灰度发布 (5% → 50% → 100%)
    ↓ 持续
监控崩溃率 → 确认修复有效 → 记录 Postmortem
```

### Postmortem 模板

```markdown
## 事故报告: [标题]

- 发生时间: yyyy-mm-dd HH:MM
- 影响范围: [N] 用户受影响
- 根因: [技术原因]
- 修复: [PR #xxx]
- 预防措施: [添加监控/测试/代码规范]
- 责任人: [姓名]
```

## 🏷️ 发布命令

```bash
# [SHELL] 标准发布
git checkout main && git pull
git tag -a v1.2.3 -m "Release v1.2.3"
git push origin v1.2.3

# [SHELL] 热修复
git checkout main
git checkout -b hotfix/crash-fix
# 修复 → 提交 → PR → 合并
git checkout main && git pull
git tag -a v1.2.4 -m "Hotfix v1.2.4: fix crash on null pointer"
git push origin v1.2.4
```
