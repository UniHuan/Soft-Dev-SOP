## 1. 概述与核心设计原则

HIG 包含为任何 Apple 平台设计出色体验的指导和最佳实践。三个核心设计原则：

### 层级 (Hierarchy)
建立清晰的视觉层级，使控件和界面元素提升并区分其下方的内容。

### 和谐 (Harmony)
与硬件和软件的同心设计保持一致，在界面元素、系统体验和设备之间创造和谐。

### 一致性 (Consistency)
采用平台惯例，保持适应不同窗口大小和显示器的统一设计。

## 2. 各平台设计指南

### iOS (iPhone)
- **显示**: 中等尺寸、高分辨率屏幕
- **人体工学**: 单手或双手握持，视距不超过 1-2 英尺，可横竖屏切换
- **输入**: 多点触控手势、虚拟键盘、语音控制；陀螺仪和加速度计
- **交互特点**: 短至一两分钟的快速查看，长至一小时的浏览/游戏；多应用频繁切换
- **系统特性**: Widgets、主屏幕快速操作、Spotlight、Shortcuts、Activity views
- **关键原则**:
  - 精简屏幕控件数量，让次要操作可通过最小交互被发现
  - 控件放在屏幕中下部以适应手持姿势
  - 适配外观变化（横竖屏、暗黑模式、动态字体）
  - 利用平台能力（支付、生物认证、定位）

### iPadOS
- **显示**: 大尺寸、高分辨率屏幕
- **人体工学**: 手持或放在支架上，视距约 3 英尺内
- **输入**: 多点触控、键盘、触控板、Apple Pencil、语音；常组合使用多种输入方式
- **交互特点**: 短时操作到数小时沉浸式工作；多应用同屏显示（多任务、分屏）
- **系统特性**: 多任务处理、Widgets、拖放
- **关键原则**:
  - 利用大屏提升内容，减少模态界面和全屏转换
  - 根据视距和输入方式调整内容密度
  - 适配多任务模式、暗黑模式、字体大小变化
  - 无缝转接到 macOS 运行

### macOS
- **显示**: 大屏、高分辨率，支持外接多个显示器（包括 iPad）
- **人体工学**: 静止使用，设备放在桌面，视距 1-3 英尺
- **输入**: 物理键盘、指点设备、游戏控制器、Siri 的任意组合
- **交互特点**: 快速任务到数小时深度专注；多应用同时打开，平滑切换
- **系统特性**: 菜单栏、文件管理、全屏模式、Dock 菜单
- **关键原则**:
  - 利用大屏减少嵌套层级和模态使用
  - 支持窗口大小调整、全屏模式
  - 使用菜单栏提供所有命令的便捷访问
  - 支持高精度输入完成像素级操作
  - 键盘快捷键加速操作
  - 允许个性化定制（工具栏、窗口配置、颜色字体）

### visionOS (Apple Vision Pro)
- **空间**: 无限 3D 画布，可查看窗口、体积和 3D 对象
- **沉浸**: Shared Space（多应用并存）↔ Full Space（独占运行）
- **穿透 (Passthrough)**: 实时外部摄像头视频；Digital Crown 控制穿透程度
- **空间音频**: 结合声学和视觉传感建模，使音频在空间中自然发声
- **眼和手**: 主交互方式——用眼睛看虚拟对象 + 间接手势（如轻点）激活
- **人体工学**: 完全依赖摄像头，视觉舒适度至关重要；内容自动放置于佩戴者头部相对位置
- **可及性**: 支持 VoiceOver、Switch Control、Dwell Control、Head Pointer 等
- **关键原则**:
  - 中心内容放在视野内
  - 避免内容锚定到头部（应锚定在空间中）
  - 使用深度传达层级
  - 提供准确的深度视觉线索避免不适

### watchOS
- **显示**: 小尺寸、高分辨率、腕戴式
- **人体工学**: 抬腕查看，视距不超过 1 英尺；Always On 显示
- **输入**: Digital Crown（垂直导航/滚动）、轻点/滑动/拖拽手势、Action button
- **交互特点**: 全天多次抬腕查看，每次交互少于 1 分钟；复杂功能、通知和 Siri 比 App 本身更常用
- **系统特性**: Complications（复杂功能）、通知、Always On、表盘
- **关键原则**:
  - 支持快速、可扫视的单屏交互
  - 最小化导航层级深度
  - 用 Digital Crown 进行垂直导航
  - 主动预测需求，提供上下文相关内容
  - 用复杂功能在表盘上提供动态数据

## 3. 设计基础 (Foundations)

### 3.1 可及性 (Accessibility)
可及界面三大特质：
- **直觉性 (Intuitive)**: 使用熟悉且一致的交互使任务简单直接
- **可感知性 (Perceivable)**: 不依赖单一方式传达信息（视觉、听觉、语音、触觉均可）
- **适应性 (Adaptable)**: 通过系统可及性功能或个性化设置适应不同使用方式

**具体指南**:
| 平台 | 默认字号 | 最小字号 |
|------|---------|---------|
| iOS/iPadOS | 17pt | 11pt |
| macOS | 13pt | 10pt |
| tvOS | 29pt | 23pt |
| visionOS | 17pt | 12pt |
| watchOS | 16pt | 12pt |

- 字号放大建议 ≥200%（watchOS ≥140%），使用 Dynamic Type
- 细体字需要更大的推荐尺寸
- 色彩对比度最低标准（WCAG Level AA）：≤17pt 文本需 4.5:1，≥18pt 文本需 3:1，粗体文本需 3:1
- Dark Mode 和 Increase Contrast 下也需检查对比度

### 3.2 App 图标 (App Icons)
- 是品牌和用户体验的关键：出现在主屏幕、搜索结果、通知、设置、分享菜单
- **分层设计**:
  - iOS/iPadOS/macOS/watchOS: 背景层 + 一或多个前景层，呈现 Liquid Glass 属性（高光、霜感、半透明）
  - tvOS: 2-5 层，获得焦点时产生视差效果
  - visionOS: 背景层 + 1-2 上层，形成 3D 对象，查看时微微扩展
- 使用 Icon Composer（Xcode 附带）导入和调整 iOS/macOS/watchOS 图标层
- 前景层边缘应清晰（避免柔化/羽化）
- 不同前景层使用不同透明度增加深度感
- 背景使用微妙的从上到下、由浅到深的渐变
- 优先使用矢量图形（SVG/PDF），避免光栅图

### 3.3 颜色 (Color)
- 系统颜色在不同背景和外观模式下自动适配
- **最佳实践**:
  - 不要用同一颜色表达不同含义
  - 确保所有颜色在亮/暗/高对比度下都有效
  - 在不同光照条件下测试（True Tone 显示会影响颜色）
  - 考虑艺术作品和半透明效果对邻近颜色的影响
  - 让用户选择颜色时使用系统提供的颜色选择器
- 为自定义颜色提供亮/暗变体以及高对比度选项
- 即使只发布一种外观模式，也要提供两种颜色以支持 Liquid Glass 适配性

### 3.4 版式 (Typography)
- **SF 字体家族**: San Francisco (SF Pro, SF Compact, SF Mono 等) — 无衬线
- **NY 字体家族**: New York — 衬线，可单独使用或与 SF 搭配
- 一般避免细字重（Ultralight, Thin, Light），优先使用 Regular, Medium, Semibold, Bold
- 最小化使用的字体种类
- 字号变大时优先保障重要内容（不是屏幕上每个字都需要变大）
- 可变字体格式支持光学尺寸（optical sizing）——不同尺寸自动调整字体设计

### 3.5 布局 (Layout)
- **分组相关项**: 使用负空间、背景形状、颜色、材质或分隔线
- **给重要信息足够空间**: 不要被非必要细节挤压
- **内容延伸到屏幕边缘**: 背景和全屏作品延伸到显示边缘
- **视觉层级**:
  - 用 Liquid Glass 材质区分控件和内容
  - 按阅读顺序（从上到下、从前往后）放置重要项目
  - 对齐组件使界面整洁、便于扫描
  - 使用渐进式披露（progressive disclosure）隐藏次要内容
  - 控件之间保持足够空间
- **适应性**: 适应设备或窗口大小变化

### 3.6 材质 (Materials)
- **Liquid Glass** (新设计语言):
  - 形成浮于内容层之上的独立功能层
  - 用于控件和导航元素（标签栏、侧边栏等）
  - 内容可从下方滚动透出，创造动感和深度
  - **不要在内容层中使用 Liquid Glass**
  - **节制使用** Liquid Glass 效果
  - 两种变体：
    - **常规 (regular)**: 模糊并调整背景亮度——大多数系统组件使用
    - **透明 (clear)**: 高度半透明——适合媒体背景上的组件
- **标准材质**: 用于内容层内的视觉区分

### 3.7 图标 (Icons)
- 高度简化的可识别设计
- 保持视觉一致性：统一的尺寸、细节程度、描边粗细、透视
- 图标粗细应与邻近文字匹配
- 必要时添加内边距实现视觉居中（光学对齐而非几何居中）
- 只在必要时提供选中状态图标（系统会自动处理）
- 使用包容性图像（性别中立的人物形象）
- 仅在传达含义必需时在图标中包含文字

### 3.8 动效 (Motion)
- 目的明确地添加动效，不要为动而动
- 使动效可选（提供触觉和音频替代）
- 反馈动效应真实、跟随手势
- 频繁交互的 UI 一般不需添加动效
- 让用户可取消动效
- 游戏: 保持 30-60 fps 帧率；让用户自定义视觉体验以优化性能/电池

### 3.9 暗黑模式 (Dark Mode)
- 系统级外观设置，使用暗色调色板适配低光环境
- **避免提供应用内独立的外观设置**（增加用户管理成本）
- 测试两种外观模式下的可读性
- 语义颜色自动适配当前外观
- 自定义颜色在 Xcode asset catalog 中添加 Color Set
- 最低对比度 4.5:1，小文本追求 7:1
- 柔化白色背景图像以防在暗黑模式下发光
- 使用 SF Symbols（自动适配暗黑模式）

### 3.10 品牌 (Branding)
- 在文字沟通中使用品牌的独特声音和语调
- 考虑选择强调色（accent color）
- 可考虑使用自定义字体（标题用自定义字体，正文用系统字体）
- **品牌始终让位于内容**
- 避免在整个应用中反复显示 Logo
- 启动画面不是品牌展示机会

### 3.11 写作 (Writing)
- 确定应用的"声音"（voice）——谁会使用？想传达什么感受？
- 语气（tone）随情境变化
- **清晰**: 使用易于理解的词语，能少则少
- **面向所有人**: 简单平实的语言，考虑可及性和本地化
- 以行动为导向——按钮和链接使用动词
- 建立语言模式保持一致性

### 3.12 包容性 (Inclusion)
- 包容性设计考虑维度：年龄、性别认同、种族、性取向、身体/认知属性、残障、语言文化、宗教、教育、政治观点、社会经济背景
- 使用平实、包容的语言
- 用"你/你的"直接称呼用户
- 避免使用无法被所有人理解或可能有冒犯性的图像和隐喻

### 3.13 隐私 (Privacy)
- **仅请求真正需要的数据访问权限**
- 透明说明数据如何收集和使用
- 尽可能在设备端处理数据（如使用 Apple Neural Engine）
- 需要请求权限访问的内容：个人数据、用户生成内容、受保护资源（蓝牙/WiFi）、设备能力（相机/麦克风）、广告标识符
- App Store 产品页上显示隐私详情

### 3.14 图片 (Images)
- 提供高分辨率素材，覆盖所有支持的设备
- 比例因子: iOS @2x/@3x, iPadOS/watchOS @2x, macOS/tvOS @1x/@2x
- 格式: 位图用 PNG，照片用 JPEG/HEIC，平面图标用 PDF/SVG
- 包含颜色配置文件

### 3.15 SF Symbols
- 数千个一致、高度可配置的符号
- 四种渲染模式: Monochrome, Hierarchical, Palette, Multicolor
- 符号图层: Primary → Secondary → Tertiary
- 使用系统颜色确保自动适配外观变化
- **不能用于 app 图标、logo 或商标用途**

### 3.16 空间布局 (Spatial Layout) — visionOS
- 重要内容放在视野中心
- 避免将内容锚定到佩戴者头部
- 使用深度传达层级
- 提供准确深度视觉线索避免不适

## 4. 设计模式 (Patterns)

### 4.1 导航与搜索 (Navigation and Search)
- 路径控件、搜索栏、侧边栏、标签栏、Token 字段

### 4.2 模态 (Modality)
- **定义**: 在独立专用模式下呈现内容，阻止与父视图交互，需要明确操作来关闭
- **用途**: 获取关键信息、确认操作、完成特定任务、提供沉浸体验
- **使用原则**:
  - 仅在明确有益时使用模态
  - 模态任务保持简单、简短、精简
  - 避免创建"应用中的应用"（模态视图内不应再有复杂层级）
  - 全屏模态适合深度内容或复杂任务
  - **始终提供明显的关闭方式**
  - 关闭前如可能丢失数据需确认
  - 提供标题说明模态视图的任务

### 4.3 加载 (Loading)
- **目标**: 在用户意识到之前完成加载
- **原则**:
  - 尽快展示内容（占位文本/图形/动画）
  - 后台加载时让用户做其他事情
  - 长时间加载提供有趣内容查看
  - 使用 Background Assets 框架在后台下载大型资源
- **进度指示**:
  - 知道时长 → 确定进度条 (determinate)
  - 不知道时长 → 不确定进度条 (indeterminate)
- 游戏可创建自定义加载界面
- watchOS: 尽量避免加载指示器

### 4.4 引导 (Onboarding)
- **理想情况**: 用户通过体验本身就能理解应用，无需引导
- **如需引导**: 设计快速、有趣、可选的流程
- **通过互动教学**: 让用户实际操作而非被动阅读
- 提供上下文相关的提示（使用 TipKit）
- 引导内容聚焦于你提供的体验（不教如何使用系统/设备）
- 启动画面 (splash screen) 简洁、信息可一眼吸收
- 推迟非必要设置和权限请求
- 权限请求可融入引导流程，说明为什么需要和好处

### 4.5 反馈 (Feedback)
- **目的**: 让用户知道发生了什么、接下来可做什么、理解操作结果、避免错误
- **类型**: 状态信息 → 被动显示；警告（如数据丢失）→ 需要打断用户
- **最佳实践**:
  - 所有反馈方式都需可及（颜色+文本+声音+触觉）
  - 状态反馈融入界面（如 Mail 工具栏显示未读数量）
  - 警报仅用于关键且可操作的信息
  - 仅在意外且不可逆的数据丢失时警告
  - 重要操作完成后确认
  - 命令无法执行时说明原因

### 4.6 通知管理 (Managing Notifications)
- 必须先获得权限
- **Focus 模式集成**: 用户可指定哪些联系人和应用能突破专注模式
- **四个中断级别**:
  1. **Passive（被动）**: 闲时查看，如餐厅推荐
  2. **Active（活跃，默认）**: 到达时可能想知道，如比分更新
  3. **Time Sensitive（时效性）**: 直接影响用户，需立即关注，如账户安全问题
  4. **Critical（紧急）**: 健康安全紧急信息，极其罕见

### 4.7 设置 (Settings)
- 提供对最多人数最优体验的默认设置
- **最小化设置数量**
- 将设置放在用户期望的位置（菜单栏、Command-, 快捷键、游戏 Esc 键）
- 不要用设置请求可通过其他方式获取的信息
- **尊重系统级设置**，不重复系统全局选项

### 4.8 拖放 (Drag and Drop)
- 尽可能全面支持拖放
- 提供拖放的替代方式（菜单命令、可及性 API）
- 同容器内拖放→移动；不同容器→复制；应用间→始终复制
- visionOS: 捏合并保持，沿任意方向（包括 z 轴）拖放

### 4.9 启动 (Launching)
- **立即启动**: 用户希望在几秒内开始交互
- iOS/iPadOS/tvOS 需要启动画面 (launch screen)——应与第一屏几乎相同
- **不要在启动画面上放文字**（不会本地化）、不要做广告
- 恢复之前状态（滚动位置、窗口状态和位置）
- 启动画面不是 splash screen 或品牌展示机会

### 4.10 多任务 (Multitasking)
- 除少数例外（如某些游戏、Full Space visionOS 应用），所有应用都需与多任务良好配合
- 用户切换时暂停需要注意力/参与的活动
- 平滑响应音频中断
- 在后台完成用户发起的任务
- 适度使用通知

### 4.11 全屏 (Going Full Screen)
- iPhone/iPad/Mac 支持全屏模式
- 适合游戏、媒体观看、需要无干扰环境的深度任务
- 保持基本功能和控件的可访问性
- 除游戏外，允许用户在全屏模式下访问 Dock
- 全屏模式不因切换应用自动结束

### 4.12 撤销与重做 (Undo and Redo)
- 帮助用户预测撤销/重做的结果
- 显示撤销/重做的结果（如果影响的内容不在屏幕上，滚动到那里）
- 允许多次撤销
- 仅在必要时提供专用撤销/重做按钮（用户期望 Edit 菜单、键盘快捷键、摇动 iPhone）

### 4.13 图表数据 (Charting Data)
- 使用图表突出数据集中的重要信息
- 保持简洁，让用户选择何时查看额外细节
- 每个图表都需可及（可及性标签描述值和组件）
- 优先使用常见图表类型（条形图、折线图）

## 5. 组件 (Components)

组件分为七大类别：

| 类别 | 包含组件 |
|------|---------|
| **Content（内容）** | Charts, Image views, Text views, Web views |

## 6. 输入方式 (Inputs)

- **Action button** (Apple Watch Ultra)
- **Apple Pencil and Scribble**
- **Camera Control**
- **Digital Crown** (Apple Watch, Vision Pro)
- **Eyes** (visionOS 主交互)
- **Focus and selection** (tvOS 遥控器焦点系统)
- **Game controls** (游戏控制器)
- **Gestures** (手势 — 见下文)
- **Gyroscope and accelerometer**
- **Keyboards** (物理/虚拟键盘)
- **Nearby interactions** (近距离交互)
- **Pointing devices** (指点设备)
- **Remotes** (遥控器)

### 手势 (Gestures) 核心指南
- 提供多种交互方式（不只依赖手势——支持语音、键盘、Switch Control）
- 以符合用户期望的方式响应手势
- 尽可能响应式处理手势，提供即时反馈
- 手势不可用时需明确指示
- **自定义手势**:
  - 仅在必要时添加（游戏、绘图应用等）
  - 必须是：可发现、简单易执行、与其他手势区分、不是执行重要操作的唯一方式
  - 用于补充标准手势，而非替代
  - 避免与系统手势冲突（如 watchOS 边缘滑动、visionOS 系统覆盖层手势）

## 8. 实用设计清单

### 启动前检查
- [ ] App 图标是否使用分层设计（各平台适用对应层数）？
- [ ] 是否提供 @2x 和 @3x 资源（按平台需求）？
- [ ] 启动画面是否与第一屏几乎相同（iOS/iPadOS/tvOS）？
- [ ] 是否已请求且仅请求必要的数据权限？

### 可及性检查
- [ ] 是否支持 Dynamic Type（至少 200% 放大）？
- [ ] 色彩对比度是否达到 WCAG AA 标准？
- [ ] 是否提供多种反馈方式（视觉+声音+触觉）？
- [ ] 是否用 Accessibility Inspector 审计过？
- [ ] 图标和图像是否包容性？

### 外观适配检查
- [ ] 亮色/暗色模式下是否都测试通过？
- [ ] Increase Contrast 开启时是否正常？
- [ ] Reduce Transparency 开启时是否正常？
- [ ] 是否避免提供应用内独立外观设置？

### 交互检查
- [ ] 模态使用是否必要且简单？
- [ ] 所有模态视图是否都有明显的关闭方式？
- [ ] 加载体验是否让用户有事可做？
- [ ] 是否支持多任务和状态恢复？
- [ ] 手势是否有替代操作方式？
- [ ] 反馈是否匹配信息重要性？

### Liquid Glass 检查 (iOS/iPadOS/macOS)
- [ ] 是否使用 Liquid Glass 区分控件层和内容层？
- [ ] 是否避免在内容层使用 Liquid Glass？
- [ ] 是否节制使用自定义 Liquid Glass 效果？
- [ ] 媒体背景组件是否使用 clear 变体？

### 平台专项检查
- **iOS**: 控件是否在便于手持操作的位置？
- **iPadOS**: 是否支持多任务分屏和拖放？
- **macOS**: 菜单栏是否包含所有命令？是否支持键盘快捷键？
- **visionOS**: 内容是否锚定在空间中？深度线索是否准确？
- **watchOS**: 是否支持快速单屏交互？是否提供复杂功能？
